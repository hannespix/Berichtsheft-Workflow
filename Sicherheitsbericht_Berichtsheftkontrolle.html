1. Architektur & Sicherheitskonzept

1.1 Was ist die Berichtsheftkontrolle?

Verwaltungstool für die Ausbildungsberater Gärtner am RP Freiburg zur Planung, Durchführung und Nachverfolgung von Berichtsheftdurchsichten. Das Tool verwaltet ca. 300–500 Auszubildende mit Stammdaten, Kontrollergebnissen, Wiedervorlagen und Korrespondenz.

1.2 Architektur-Entscheidungen

Die Architektur wurde bewusst für den Verwaltungskontext gewählt:

  • Rein lokale Ausführung – Einzelne HTML-Datei (~5,8 MB) im Browser (Chrome/Edge). Kein Server, kein Backend, keine Cloud. Die Angriffsfläche ist fundamental kleiner als bei jeder Server-Client-Architektur.
  • File System Access API – SQLite-Datenbank auf dem geschützten Netzlaufwerk des RP. Zugriffskontrolle über NTFS-Berechtigungen und Windows-Domäne.
  • Offline-fähig – Alle 12 Bibliotheken lokal gebündelt. Kein CDN, kein Internet-Zugriff nötig oder möglich. Content Security Policy blockiert aktiv alle externen Verbindungen.
  • Keine Installation – Kein Admin-Zugriff, keine Softwareverteilung, keine Registry-Einträge. Passt zur Zero-Trust-Umgebung.

1.3 Angriffsfläche (Attack Surface)

Nicht vorhanden (kein Risiko):
Kein Netzwerk-Traffic (kein MITM) • Kein Server (kein RCE) • Kein Login (kein Credential-Stuffing) • Keine API-Endpunkte • Keine Cookies/Sessions • Keine externen Ressourcen (kein CDN-Supply-Chain-Angriff)
Verbleibende Angriffsfläche:
Lokaler Dateizugriff → geschützt durch NTFS + Domäne • SQLite auf Netzlaufwerk → geschützt durch Berechtigungen • Datei-Imports (CSV/Excel) → validiert mit Größenlimits + Typ-Prüfung • Browser-Sandbox → geschützt durch Chrome/Edge

1.4 Warum keine Authentifizierung?

Die App läuft auf Zero-Trust-Windows-PCs im RP-Netzwerk. Jeder Nutzer ist bereits über Windows-Domäne authentifiziert und autorisiert (Netzlaufwerk-Berechtigung). Eine App-eigene Authentifizierung wäre:

  • Redundant zur bestehenden Windows-Authentifizierung
  • Weniger sicher als Active Directory (selbstgebaut vs. Domäne)
  • Unpraktisch für 2–3 Sachbearbeiter die schnell wechseln

Die Prüfer-Auswahl im Tool dient ausschließlich der Nachvollziehbarkeit (wer hat wann welche Kontrolle durchgeführt), nicht der Zugriffskontrolle.

  • SQLite unverschlüsselt (Netzlaufwerk-Schutz)
  • Kein vollständiges Audit-Log (Overengineering für 2–3 User)
